## 1. Protected Assets
1. **Ed25519 Authority Signing Key (`seed_file` / `SHARK_ED25519_SEED_HEX`):** 32-byte private key seed used to sign `intentseal-vrk-claim-v2` ledger entries and `intentseal-vrk-head-v2` head commitments. Never stored in the repository, `.env.example`, or CI logs.
2. **VRK v0.3.1 Hash-Chained Ledger & Timestamped Head (`SharkProtocolEngine.ledger`):** Append-only SHA-256 hash chain anchored at `f010a99d78b360b8fd5dc9b727f21b898889c6e75e3093cc22d6f04d005a0d0f` ([10.5281/zenodo.23018459](https://doi.org/10.5281/zenodo.23018459)), committing to `prompt_sha256`, `response_sha256`, `lrsc_sha256`, `uncompressed_ring_sha256`, on-disk `evidence_root`, and a signed `(head_index, ledger_length, head_hash, issued_at)` head commitment (`intentseal-vrk-head-v2`).
3. **Per-Tenant Ledgers & Request-Lifecycle Slots (`RequestSlot`, `WorkerEpochGuard`):** Per-tenant `.jsonl` ledgers persisted on disk with `os.fsync`, and in-memory request slots governed by the 6-state lifecycle automaton (`UNINIT -> PARTIAL_INIT -> SEALED_ACTIVE -> SHUTDOWN_CLEAN -> ZEROED_FREED`, with `OOM_ABORT -> ABORTED_POISONED`) and monotonic worker-epoch checks (`slot_epoch == worker_epoch`).
4. **Upstream Cloud Provider API Keys (`GROQ_API_KEY`, `TOGETHER_API_KEY`, `GEMINI_API_KEY`, `HUGGINGFACE_API_KEY`):** External credentials loaded from local environment variables.

## 2. Adversary Model
- **A1 — Unauthenticated Ledger Forger, Truncator, or Stale-Head Replayer:** Attempts to append a forged single-parent or multi-parent tail entry, rewrite historical entries without the authority private seed, sign with an arbitrary attacker key or denylisted public test seed, truncate the tail of an exported ledger without a head record, or truncate a ledger and attach an older valid head of shorter length or earlier timestamp.
- **A2 — Unauthenticated or Malicious Tenant Client:** Attempts to present an unknown Bearer token, spoof another tenant's `tenant_id` in the JSON body, rotate fake Bearer tokens on loopback to evade per-tenant rate limits or evict existing tenants' ledgers, send oversized HTTP payloads (`> 64 KiB`), or hold server threads open via slow-loris socket stalls.
- **A3 — Concurrent In-Process Worker Race / Stale Epoch Reader:** Attempts to read a request slot from a prior worker epoch (`slot_epoch != worker_epoch`), dereference a `PARTIAL_INIT` or `ABORTED_POISONED` slot after an exception/OOM abort, or mutate a terminal `ZEROED_FREED` slot.
- **A4 — Compromised Parent Gateway Against Child Signer (`IsolatedSignerSubprocess`):** Attempts to inspect the parent process's Python heap or environment for the Ed25519 private seed, issue an unauthorized IPC key-export command, ask the child signer to sign a historical fork (`prev_hash != last_signed_digest`), or ask the child to sign a truncated head commitment.

## 3. Architectural Controls & Scope Limits
- **Mandatory Key Configuration & Denylist Enforcement:** `Ed25519AuthoritySigner` requires the OpenSSL-backed `cryptography` package and refuses to start (`RuntimeError`) if no seed is supplied. Known public test seeds (`SHA-256: 914f28ea...`, pubkey `e3ad8106...`) are permanently blocked.
- **Pinned Public-Key Verification, `issued_at` Timestamps & `verify_exported_ledger`:** `SharkProtocolEngine.verify_chain_list` requires `expected_pubkey` as a mandatory keyword-only argument. `SharkProtocolEngine.verify_exported_ledger(chain, signed_head, expected_pubkey, min_length, ...)` requires a non-empty `signed_head` (`intentseal-vrk-head-v2` with ISO-8601 UTC `issued_at >= chain[-1]["timestamp_utc"]`) and enforces `len(chain) >= min_length`, optional `min_issued_at`, and optional `expected_head_hash` (reference release head hash in `data/release_head.json`: `866e1919b5a3e9e1e896496f735fdc94846e03497533b74f6fe3a5a96608ee5b`).
- **Token Registry (`sha256(token) -> tenant_id`), Per-Tenant Persistence & Non-Evicting Cap:** `MultiProviderGateway` authenticates Bearer tokens against a constant-time token registry mapping `sha256(token)` to `tenant_id`, rejecting unknown tokens with HTTP `401 Unauthorized` (including unauthenticated `Authorization` headers on loopback), blocks cross-tenant `tenant_id` spoofing, persists per-tenant ledgers to `<ledger_dir>/<tenant_id>.jsonl` with `os.fsync`, enforces per-tenant sliding-window rate limits (HTTP `429`), sets a `10.0s` socket timeout on `GatewayHTTPHandler`, and returns HTTP `503 Service Unavailable` (`GatewayCapacityError`) when `max_tenants` is reached instead of evicting existing tenant ledgers.
- **Stateful Child-Process Signer (`IsolatedSignerSubprocess`) & Exact Security Boundary:** When initialized via `seed_file` or `generate_ephemeral=True` (without setting `SHARK_ED25519_SEED_HEX` in the parent environment), the private seed never enters the parent gateway process's heap or environment block. Furthermore, the child daemon tracks `last_signed_digest` and `signed_count`, refusing to sign any entry whose `prev_hash != last_signed_digest` or any head whose `(head_hash, ledger_length)` does not match its current state. **Explicit Boundary Limit:** Because the child signer is an append-only cryptographic oracle over a pipe, a compromised parent process that controls the IPC pipe mid-session can still submit new forward-chained entries extending the current tip (`last_signed_digest`), although it cannot rewrite prior history, fork from an earlier digest, sign a truncated head, or extract the raw private key.
- **Data File Integrity (`data/wp19_segments.json`):** The in-repo SHA-256 check (`a78a67c8ea8f4950dcf8bad6e76ebb7fe6362742ac1dbc63881cc14311d99319`) protects against accidental local file corruption; external tamper resistance relies on verifying the SHA-256 digest published in the release notes and Zenodo record.

## 4. Explicit Non-Goals (`does_not_imply`)
- **Not an OS Ring-0 Kernel or Hardware HSM:** `RequestSlot`, `WorkerEpochGuard`, and `IsolatedSignerSubprocess` operate in user-space Python (`threading.RLock` and `subprocess.Popen` pipes). They do not protect against a root/administrator attacker on the host OS (`ptrace`, `/proc/<pid>/mem`), hardware side channels, or native C/PHP interpreter memory corruption.
- **Not a Global Lipschitz Proof for Unbounded Softmax Attention:** Theorem 10 (`perturbation_budget_scaling`) proves linear scaling `0 <= L * eta_perp <= L * tau_null` for an assumed local parameter `L >= 0`.
- **Not an Unconditional Continuum Navier-Stokes Proof:** `evaluate_wp19_piecewise_duhamel_study` is an illustrative finite-segment parameter study loaded from `data/wp19_segments.json`.
